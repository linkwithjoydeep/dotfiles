# 8. Post-install

Runs on the **installed system**, logged in as your user, after the first boot.

## 8.1 Hyprland default config

**[CUSTOM]** On its first start, Hyprland writes a default config to `~/.config/hypr/hyprland.lua`. Since Hyprland 0.55 the config is written in **Lua**; the old `hyprland.conf` (hyprlang) syntax is deprecated. Its app keys expect:

| Key | Default config runs | Installed by this guide |
|---|---|---|
| `SUPER + Q` | `kitty` | kitty ✅ |
| `SUPER + R` | `hyprlauncher` | hyprlauncher ✅ |
| `SUPER + E` | `dolphin` | **nautilus**: change it (below) |

**Edit** `~/.config/hypr/hyprland.lua`:
1. Point the file manager at nautilus. Change `local fileManager = "dolphin"` to:
   ```lua
   local fileManager = "nautilus"
   ```
2. Remove the yellow "autogenerated config" warning: delete the line containing `hl.config({ autogenerated = true })`.

Hyprland reloads its config on save, so `SUPER + E` works right away. Your own Hyprland dotfiles will replace this config later; the wiki recommends splitting it into modules loaded with `require("…")`, and editor autocompletion stubs are installed in `/usr/share/hypr/stubs/`.

## 8.2 Firewall rules

```bash
sudo ufw enable
sudo ufw allow 5353/udp comment 'mDNS (avahi printer discovery)'
sudo ufw status verbose
```
> [NOTE] ufw's default `before.rules` already accepts multicast mDNS (to `224.0.0.251`). The explicit rule above also covers unicast mDNS replies and makes the intent visible in `ufw status`.

Example for later (KDE Connect / LocalSend-style apps): `sudo ufw allow 1714:1764/udp` and `sudo ufw allow 1714:1764/tcp`.

## 8.3 Secure Boot with sbctl

If you ever enable the optional TPM unlock (8.4), do this first: the TPM unlock is bound to your Secure Boot keys.

1. Reboot into the firmware setup. Enable Secure Boot and **clear/reset the keys to enter "Setup Mode"**. Save and boot Arch.
2. Check the status. It should say `Setup Mode: Enabled`:
   ```bash
   sbctl status
   ```
3. Create your keys and enroll them **together with Microsoft's keys** (`-m`). Keeping Microsoft's keys is **required** if you dual-boot Windows or have a dedicated GPU: Windows and GPU firmware (option ROMs) are signed by Microsoft. Without them you can get a black screen at boot.
   ```bash
   sudo sbctl create-keys
   sudo sbctl enroll-keys -m
   ```
4. Sign the boot files (`-s` remembers them for automatic re-signing):
   ```bash
   sudo sbctl sign -s /efi/EFI/refind/refind_x64.efi
   sudo sbctl sign -s /efi/EFI/BOOT/BOOTX64.EFI
   sudo sbctl sign -s /efi/EFI/Linux/arch-linux.efi
   sudo sbctl sign -s /efi/EFI/Linux/arch-linux-fallback.efi
   sudo sbctl sign -s /efi/EFI/Linux/arch-linux-lts.efi
   sudo sbctl sign -s /efi/EFI/Linux/arch-linux-lts-fallback.efi
   sudo sbctl verify
   ```
   Everything listed should say "signed", except the recovery UKI if you've already set it up ([9.1](09-recovery-rollback.md#91-on-disk-recovery-environment)), which stays unsigned on purpose.
5. Reboot. `sbctl status` should now show Secure Boot enabled.

From here on, re-signing is automatic: mkinitcpio signs new UKIs (sbctl ships a mkinitcpio hook), sbctl's pacman hook re-signs registered files, and `refind-sync` ([6.7](06-boot-chain.md#67-refind)) runs `sbctl sign-all`.

## 8.4 Recovery key and optional TPM2 unlock

### Recovery key

Create a recovery key and **save it somewhere offline**. It unlocks the disk if you ever forget the password:
```bash
sudo systemd-cryptenroll /dev/sda2 --recovery-key
```

### TPM2 unlock

**[OPTIONAL]** Not used in this setup, which unlocks with the disk password + auto-login ([7.3](07-desktop-services.md#73-greeter-greetd-and-tuigreet)). Documented here in case you switch.

> ⚠️ TPM auto-unlock **without a PIN** opens the disk with no password at all. **Remove the `[initial_session]` auto-login block first**, or anyone can power the machine on and reach your desktop. Prefer `--tpm2-with-pin=yes`: a short PIN, rate-limited by the TPM, with an instant unlock.

1. Make sure Secure Boot is set up (8.3) and a recovery key exists (above).
2. Install the TPM2 library (an optional dependency of systemd, not installed by this guide), then rebuild the UKIs so the initramfs includes it:
   ```bash
   sudo pacman -S tpm2-tss
   sudo mkinitcpio -P
   ```
   (`tpm2-tools` is only needed if you want to inspect the TPM by hand.)
3. Enroll the TPM, bound to Secure Boot state (PCR 7):
   ```bash
   sudo systemd-cryptenroll /dev/sda2 --tpm2-device=auto --tpm2-pcrs=7
   ```
   Add `--tpm2-with-pin=yes` to also require a short PIN at boot (recommended).
4. Check. You should see password + recovery + `systemd-tpm2` slots:
   ```bash
   sudo cryptsetup luksDump /dev/sda2
   ```

- PCR 7 = Secure Boot state/keys. The disk auto-unlocks only if the machine boots with *your* Secure Boot keys. It still works after kernel updates, since those are signed by your keys.
- If you reset the firmware or change Secure Boot, TPM unlock fails and you get the password prompt (the password slot stays). Re-enroll with:
  `sudo systemd-cryptenroll /dev/sda2 --wipe-slot=tpm2 --tpm2-device=auto --tpm2-pcrs=7`
- `sd-encrypt` tries enrolled tokens automatically, so no cmdline change is needed.
- This PCR 7 binding is why the recovery UKI must stay unsigned ([9.1](09-recovery-rollback.md#91-on-disk-recovery-environment)).

## 8.5 AUR helper: paru

`paru` is recommended over `yay` because by default it **shows the PKGBUILD for review** before building, which suits a "few AUR packages, stability first" setup. `paru-bin` skips compiling Rust.
```bash
cd /tmp
git clone https://aur.archlinux.org/paru-bin.git
cd paru-bin
makepkg -si
```
Stability tips: prefer official repos (`pacman -Ss` first), keep AUR packages few (`paru -Qm` lists them), and snap-pac snapshots every transaction so you can roll back ([9.2](09-recovery-rollback.md#92-full-system-rollback)).

## 8.6 Hyprland on NVIDIA and multi-GPU

**[NVIDIA]** / multi-GPU only. Per the Hyprland wiki (NVIDIA, Multi-GPU and uwsm pages), when you use uwsm, put env vars in **uwsm env files**, not the Hyprland config:
- `~/.config/uwsm/env`: toolkit/NVIDIA vars
- `~/.config/uwsm/env-hyprland`: `HYPR*` / `AQ_*` vars

**1. NVIDIA variables.** Run `mkdir -p ~/.config/uwsm`, then **create** `~/.config/uwsm/env` with:
```sh
export LIBVA_DRIVER_NAME=nvidia
export __GLX_VENDOR_LIBRARY_NAME=nvidia
export NVD_BACKEND=direct
export ELECTRON_OZONE_PLATFORM_HINT=auto
```
Without an NVIDIA GPU, skip the first three lines (`ELECTRON_OZONE_PLATFORM_HINT=auto` is useful on any GPU).

**2. GPU selection (`AQ_DRM_DEVICES`).** Best practice on **any machine with two GPUs** (e.g. an integrated GPU plus a dedicated one), and essential on laptops. Skip this with a single GPU.

Never use `/dev/dri/cardN` directly. The numbers are assigned at boot and can change between boots. The real PCI paths can't be used either, because their `:` clashes with the list separator. So create stable names with a udev rule.

Find the PCI addresses:
```bash
lspci -d ::03xx
```
The example below uses `01:00.0` for the NVIDIA card and `0d:00.0` for an AMD integrated GPU.

**Create** `/etc/udev/rules.d/60-gpu-dev-path.rules` (as root) containing the following, with the addresses `lspci` showed you:
```
KERNEL=="card*", KERNELS=="0000:01:00.0", SUBSYSTEM=="drm", SUBSYSTEMS=="pci", SYMLINK+="dri/nvidia-dgpu"
KERNEL=="card*", KERNELS=="0000:0d:00.0", SUBSYSTEM=="drm", SUBSYSTEMS=="pci", SYMLINK+="dri/amd-igpu"
```
Load the rule and check:
```bash
sudo udevadm control --reload
sudo udevadm trigger
ls -l /dev/dri/nvidia-dgpu /dev/dri/amd-igpu
```

**Create** `~/.config/uwsm/env-hyprland` with (desktop with the monitor on the NVIDIA card, so NVIDIA first):
```sh
export AQ_DRM_DEVICES="/dev/dri/nvidia-dgpu:/dev/dri/amd-igpu"
```
The list is in **priority order**: the first entry is the primary renderer. Any card with a monitor attached **must** be in the list. Log out and back in to apply.

> **Laptop (dual GPU):** the wiki recommends the **iGPU first** (e.g. `/dev/dri/intel-igpu:/dev/dri/nvidia-dgpu`) to save battery. The dGPU is still available for offloading games/apps (`prime-run`). Also, for Intel+NVIDIA, load `i915` first to avoid Electron stalls: `MODULES=(i915 nvidia nvidia_modeset nvidia_uvm nvidia_drm)` ([6.1](06-boot-chain.md#61-mkinitcpio-systemd-initramfs-and-early-kms)). If external monitors on NVIDIA-wired ports misbehave, try `export AQ_FORCE_LINEAR_BLIT=0`.

Other wiki notes: exit Hyprland with `uwsm stop`, not the `exit` dispatcher. Suspend: Arch's `nvidia-utils` already handles it (kernel suspend notifiers), so no extra services are needed.

## 8.7 Printer setup

**[OPTIONAL]** Services were enabled in [7.1](07-desktop-services.md#printing).

1. Make sure the printer is on (Wi-Fi or USB), then open **Print Settings** (`system-config-printer`) or http://localhost:631.
2. **Try driverless first.** Most printers made in the last decade support AirPrint/Mopria, so with avahi running they usually appear as an **IPP Everywhere / driverless** printer. No driver is needed.
3. If it's missing or prints badly, look for the vendor's Linux driver in the repos or the AUR.
   Example, Canon PIXMA E470 series: Canon's official driver is **`cnijfilter2`** in the AUR. Run `paru -S cnijfilter2`, then re-add the printer and choose the "Canon E470 series" driver.
4. Scanning (for printers with a scanner): `sudo pacman -S sane-airscan simple-scan`. It's driverless over the network as well.

## 8.8 Snapper usage

| Command | Purpose |
|---|---|
| `snapper -c root list` | List snapshots (snap-pac adds a pre/post pair on every pacman run) |
| `snapper -c root create -d "before X"` | Manual snapshot |
| `snapper -c root status N..M` | What changed between snapshots N and M |
| `snapper -c root undochange N..M` | Revert those file changes |

For a **full system rollback** (kernel included), see [9.2](09-recovery-rollback.md#92-full-system-rollback).

## 8.9 btrfs cheat-sheet

| Command | Purpose |
|---|---|
| `sudo compsize -x /` | Real on-disk size vs uncompressed (zstd savings) |
| `sudo btrfs filesystem usage /` | Real free space (`df` isn't accurate on btrfs) |
| `sudo btrfs scrub status /` | Last scrub result (the timer runs monthly, [7.4](07-desktop-services.md#74-maintenance-timers)) |
| `sudo btrfs subvolume list /` | All subvolumes, including snapshots |
| `sudo btrfs balance start -dusage=50 /` | Reclaim half-empty data chunks if you get "no space" while df shows free space |
